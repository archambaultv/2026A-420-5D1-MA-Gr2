# Sprint 1 — version alpha

- **Pondération** : 20 %
- **Remise** : jeudi 1<sup>er</sup> octobre 2026 à 23 h 59

:::note[Dates importantes]

Quatre rendez-vous structurent ces trois semaines :

- **Lundi 21 septembre** — point de contrôle 1 : votre méthode de travail agile
  est en place;
- **Lundi 28 septembre** — point de contrôle 2 : l'application démarre à partir d'un
  clone neuf et un premier récit est terminé;
- **Jeudi 1<sup>er</sup> octobre, 23 h 59** — remise : étiquette `alpha-v1` sur le
  dépôt;
- **Jeudi 8 octobre** — revue de sprint de 20 minutes avec votre équipe : vous me
  montrez l'application.

Vous devez être présent à tous les rendez-vous. Si vous ne pouvez pas,
prévenez-moi **avant**.

:::

## But du sprint 1

En trois semaines, votre équipe livre la **version alpha** : le socle de
l'application, sur lequel les sprints 2 et 3 vont construire. Le mot *alpha*
est à prendre au sérieux. On ne vous demande ni une application complète ni une
interface léchée. On vous demande une application **qui existe** : elle démarre
avec Docker sur n'importe quelle machine, sa base de données est en place,
les parcours que vous engagez fonctionnent de bout en bout et une chaîne
d'intégration continue exécute vos tests à chaque poussée. C'est exactement la
ligne « sprint 1 » du
[tableau](../1_soumission.mdx#4-plan-des-trois-sprints--04-sprintsmd) que vous
avez utilisé pour planifier dans la soumission. Ce sprint est aussi votre
premier tour complet de la boucle décrite dans les notes de cours [Le
sprint](../../notes_de_cours/agile/6_sprint.mdx) : planification, mêlées,
revue, rétrospective.
